# Database Design Principles

## 1. Database

دیتابیس اصلی پروژه PostgreSQL و ابزار دسترسی داده Prisma است.

Schema پروژه به‌صورت چندفایلی سازمان‌دهی شده است. مسیر دقیق schema و migration باید از تنظیمات Prisma پروژه خوانده شود.

## 2. Known Identity Models

مدل‌های شناخته‌شده در دامنه Identity:

- `User`
- `AuthSession`
- `OtpChallenge`

مدل‌های شناخته‌شده دیگر شامل `PatientProfile`، `DoctorProfile`، `DoctorWeeklyAvailability`، `AvailabilityOverride` و `Appointment` هستند. جزئیات نهایی هر مدل باید با schema فعلی تطبیق داده شود.

## 3. Data Modeling Rules

- برای رابطه‌ها Foreign Key تعریف شود.
- برای داده‌های یکتا Unique Constraint در دیتابیس وجود داشته باشد.
- فیلدهای جست‌وجو و join پرتکرار با Index مناسب پشتیبانی شوند.
- حذف آبشاری فقط با تصمیم روشن دامنه استفاده شود.
- تاریخ‌های تقویمی و timestampها از هم تفکیک شوند.
- داده‌های حساس پزشکی حداقل‌سازی و با دسترسی محدود محافظت شوند.

## 4. Transactions

Transaction برای عملیات‌هایی مانند موارد زیر لازم است:

- مصرف OTP و ایجاد کاربر و Session.
- رزرو نوبت و تغییر وضعیت مرتبط.
- لغو یا جابه‌جایی نوبت در صورت نیاز به چند تغییر وابسته.
- ثبت Visit و Prescription در یک عملیات دامنه‌ای، اگر یکپارچگی آن‌ها لازم باشد.

## 5. Appointment Concurrency

برای جلوگیری از رزرو تکراری یک زمان:

1. قواعد یکتایی و هم‌پوشانی را در سطح دیتابیس طراحی کنید.
2. صرفاً به بررسی آزاد بودن Slot در لایه Application اکتفا نکنید.
3. رزرو را در Transaction انجام دهید.
4. خطای تعارض را به پاسخ قابل فهم مانند `409 Conflict` تبدیل کنید.
5. تست Integration هم‌زمانی بنویسید.

بسته به مدل نهایی، می‌توان از Unique Constraint یا قیدهای پیشرفته PostgreSQL برای جلوگیری از بازه‌های هم‌پوشان استفاده کرد.

## 6. Migration Policy

- از `migrate reset` روی دیتابیس دارای داده استفاده نکنید مگر اینکه حذف داده صریحاً موردنظر و تأیید شده باشد.
- SQL تولیدشده برای migrationهای حساس را قبل از اعمال بازبینی کنید.
- Migrationهای اعمال‌شده را ویرایش نکنید؛ migration جدید بسازید.
- قبل از تغییرات مهم backup بگیرید.
- وضعیت migration را پس از اعمال بررسی کنید.

## 7. Data Privacy

- داده واقعی بیمار را در محیط Development استفاده نکنید.
- اطلاعات پزشکی را در Log عمومی ثبت نکنید.
- دسترسی به داده‌ها بر اساس نقش، مالکیت و رابطه درمانی کنترل شود.
- سیاست نگهداری، حذف و export داده باید پیش از Production تعریف شود.
